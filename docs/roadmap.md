# Roadmap after the silence foundation

These are ordered future milestones, not implemented features. Each milestone
must preserve the [realtime contract](realtime-contract.md) and extend behavior
tests before claiming completion. Add concrete types and dependencies only when
their milestone needs them.

| Order | Milestone and responsibility                                                                                                                                                          | Acceptance                                                                                                                                                                                                                                                                                                                                                    |
| ----- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 1     | Offline low-amplitude sine oscillator in `daw-engine`, retaining phase across blocks. `daw-app` coordinates offline rendering; CLI performs WAV encoding/file I/O outside rendering.  | A known frequency/amplitude produces finite samples and continuous phase; equal frame totals and command boundaries give equivalent output across block partitions, including partial blocks. A WAV has the requested rate, channels, exact frame count, and signal. Existing transport/silence contracts are deliberately updated and regression tests pass. |
| 2     | The same oscillator through `daw-audio`/CPAL, with gain ramps in the engine and bounded control commands.                                                                             | Native output matches offline behavior; ramps avoid abrupt gain discontinuities. Measure callback deadlines, allocations, continuity, and load in release on identified hardware. Record device/configuration and observed failures; silence-era smoke is insufficient evidence.                                                                              |
| 3     | Sampler and fixed voice pool in the engine; asset loading/decoding and ownership preparation in the application/audio control side.                                                   | Known sample fixtures render at scheduled positions, voice limits have a defined policy, and playback performs no loading, decoding, allocation, or blocking in the callback. Test exhaustion and asset lifetime through shutdown.                                                                                                                            |
| 4     | Four-channel mixer: channel state in the document, gain/pan/mute and meter accumulation in the engine, bounded meter publication in audio, controls in React via the application.     | Deterministic four-channel fixtures verify gain, pan law, mute, summing, and defined output-level policy. Meter updates remain bounded and match rendered samples without callback IPC.                                                                                                                                                                       |
| 5     | 16-step sequencer: editable patterns in domain, scheduling and within-block event offsets in engine, use cases in application, controls in UI.                                        | Identical musical event positions across block partitions, tempos with fractional frames per step, and tempo changes. Specify rounding/drift behavior and test Play/Pause/Stop without duplicate or skipped boundary events.                                                                                                                                  |
| 6     | Versioned document, save/open, relative assets, and beat export. Domain defines versioned musical data; application coordinates migration/path resolution; adapters perform file I/O. | Save/open round-trips fixtures; unsupported versions, missing assets, and invalid paths have explicit errors. Export has exact duration and agrees with deterministic offline rendering. No persistence or filesystem access runs in the callback.                                                                                                            |
| 7     | Clips and scenes, followed by timeline, piano roll, and automation. Domain represents arrangements; engine schedules transitions; application and UI edit/launch them.                | Define launch/quantization and scene-transition rules, then test them across block sizes and tempo changes. Editing and playback remain distinct, with bounded command and observation behavior.                                                                                                                                                              |

Recording, external MIDI, time stretching, VST/CLAP hosting, complex routing,
latency compensation, and collaboration remain later work. They are not implied
by completing the milestones above.

The next concrete change is milestone 1: add the offline oscillator inside
`daw-engine` using the existing render contract, then verify it and expose WAV
output through an offline adapter. Stage 6 adds documentation and CI only.
