# Sampler integration acceptance — local closure 9.4.d

Audited 2026-11-09 against the implemented 9.4.a–c code and tests. This closes
engine/service/application/desktop integration locally. Stage 9 remains open:
physical sampler audition, native processing measurements and publication/CI
belong to 9.5. Older sine measurements and published kernel CI do not establish
those results. See the [closure report](../progress/cierre-integracion-9.4.md).

The [engine](sampler-contract.md), [service](sampler-service.md),
[desktop](sampler-desktop.md) and [preparation](sample-loading-contract.md)
contracts retain their separate ownership and observation boundaries.

The audit reproduced three failing frontend cases before fixing two defects:
device enumeration prevented the initial preparation query; effect replacement
could start a second automatic poll while an earlier invoke was still pending.
The regressions now pass. Audio DSP, queues, DTOs, dependencies and workflow are
unchanged in 9.4.d. Their earlier tests remain part of the full regression check.

## Evidence and handoff

The [9.4.d report](../progress/cierre-integracion-9.4.md) records the current full
check/build and code fingerprint. Earlier 9.3/9.4.a–c reports/manifests remain dated
snapshots. Check suites overlap; their counts must not be summed as unique tests.
Local checks are separate from hosted checks for a published revision.

The [native verification protocol](sampler-native-verification.md) defines 9.5
workloads, measured regions, artifacts and acceptance. Its originally missing diagnostic runner and deallocation telemetry are now
implemented in [9.5.a](sampler-diagnostics.md), with offline measurements. Existing
tone-check/engine-bench remain sine-specific; physical sampler verification is still pending.
Unplug, loopback, long stress, other physical formats/devices and Linux/macOS native
coverage remain pending unless separately performed and recorded.
