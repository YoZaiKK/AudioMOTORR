# Sequencer desktop integration — stage 11.3.c

Implemented locally on 2026-11-12 over [application coordination](sequencer-application.md).
The desktop now exposes pattern selection, explicit sequenced initialization,
accepted edits and applied musical observations. See the
[stage report](../progress/etapa-11-desktop-secuenciador.md) and
[Spanish walkthrough](../howToRunThis/08-secuenciador.md).

## IPC and data contract

Five new commands join the existing registered application surface, bringing it
to 25 commands: `get_pattern`, `sequencer_set_pattern`, `sequencer_set_step`,
`sequencer_set_row_slot` and `initialize_sequenced_sampler`. They share the same
blocking application adapter and main-window-only capabilities. No manual
backend initialization or test command is exposed through IPC.

`PatternDto` contains a fixed 4 × 16 boolean matrix and four slot numbers. Serde
rejects malformed lengths/types and unknown pattern fields; domain conversion
validates slot bounds before calling the application. Cell/slot edits validate
row, step and slot in the existing application layer. Full replacement is one
atomic application operation. Preparation IDs remain canonical decimal strings.

`PatternEditDto` separates selected pattern from optional acceptance. The optional
`ServiceSnapshotDto.sequencer` contains applied pattern, musical frames, position,
fraction, last boundary, cumulative counters and latest event/outcome. Every u64
and u128 is a decimal string, including loop/frame/counter values and phase
numerator/denominator. Only bounded indices and slots are JSON numbers. Bindings
are generated by ts-rs and checked against the Rust declarations.

The latest scheduled event has no application command ID. Its identity and
outcome are shown separately from explicit manual trigger receipts. It is not a
complete history; intermediate observed boundaries or outcomes may be skipped.

## Grid and lifecycle

The grid is visible near the top of the workspace. It shows four sample selectors,
64 accessible toggle buttons, beat grouping, atomic clearing and explicit pattern
refresh. Filled steps are selected document intent; dots mark steps enabled in
the observed engine pattern; the outlined column is the last actually observed
boundary. Paused position stays frozen; settled Stop clears the boundary.
The UI never schedules notes or advances a playhead from a timer.

Editing is enabled only with a connected native bridge and a known selected
pattern, while audio is uninitialized or a sequenced session is ready. Loading,
cancelling and ready banks permit document-only edits once the individual invoke
settles. Ready legacy modes require closing audio or explicitly choosing a
sequenced session. Browser mode displays disabled controls without fabricated
samples, device state or musical activity.

Sampler preparation adds **Inicializar secuenciador**, using the prepared bank ID
and selected output. It installs current pattern/mix/tempo through the application,
consumes the bank and starts stopped. The client refreshes preparation after
success or failure. Existing raw/mixed initializers and manual triggers remain.

No optimistic selection is committed before a successful edit response. Queue
or validation errors retain selected values. Offline receipts retain their
meaning after initialization. Live receipts show pending/processed/unknown;
processing confirmation comes from exact BigInt comparison of applied command
watermarks, not the current step value. A newer session cannot confirm an edit
whose session was lost, including when the invoke reply arrives after reopening.
Events arriving before invoke replies can confirm processing correctly.

Snapshot sequence ordering is lossless through BigInt. Selected-pattern query
epochs prevent late startup values or errors from replacing a refreshed/edited
document. Snapshots never overwrite selected intent. A timed-out edit can thus
leave selected and observed patterns different; the UI preserves the error and
sends no compensating edit or invented receipt.

The fixed-width grid scrolls inside its panel on narrow screens. At the normal
1000-pixel window all 16 steps fit; a 360-pixel viewport keeps the document width
bounded and scrolls the grid horizontally. Keyboard focus, pressed state and
current-step semantics are exposed independently.

## Verification and limits

Tests cover offline/live editing, replacement, exact IDs, observed-only playhead,
early/late replies, lost sessions, stale startup queries, queue/timeout errors,
preparation states, browser/legacy mode and initialization failure. IPC tests use
real application state under the mock Tauri runtime for validation, receipt/target
separation, queue-full rollback, u64/u128 JSON precision and denial from other
windows with valid arguments.

The debug desktop was built and inspected in a real Windows WebView2 window.
Sixteen UI cell edits and a row-slot change were confirmed through Rust IPC,
with audio uninitialized throughout. Wide and narrow captures plus source/binary
hashes are [recorded](screenshots/stage11-sequencer.json). Narrow viewport size
was set through CDP. This proves actual layout/edit wiring, not native playback,
audio continuity or timing. [Integrated acceptance 11.3.d](sequencer-integration-acceptance.md)
is now complete locally, with unchanged desktop production sources. Physical
audio, diagnostics and exact delivery CI remain stage 11.4. Persistence remains stage 12.
